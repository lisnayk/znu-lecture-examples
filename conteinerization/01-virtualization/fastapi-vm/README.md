# FastAPI у віртуальній машині

Один застосунок для локального та хмарного маршрутів. Python 3.10 або новіший.
Пакети верхнього рівня зафіксовано у requirements.txt; це не повне блокування
транзитивних залежностей. Фактичний склад середовища збережіть через pip freeze.

Застосунок повідомляє характеристики середовища, у якому його запущено: тип
машини та ознаки, за якими він його визначив, ядро й дистрибутив, процесори
та пам'ять, доступні процесу, обмеження cgroup, мережеві адреси, а також
власний PID, процес із PID 1 і простори імен. Код застосунку незмінний, тому
різниця у відповідях походить лише від середовища: хост, віртуальна машина,
інстанс EC2, згодом контейнер. Відомості читаються зі стандартних джерел
Linux (/proc, /sys, /etc/os-release) без додаткових пакетів.

| Маршрут | Відповідь |
|---|---|
| `/` | HTML-сторінка «паспорт середовища» |
| `/api/env` | ті самі відомості у форматі JSON |
| `/healthz` | стан процесу: `{"status": "ok"}` |

Файли: main.py (маршрути), envinfo.py (збір відомостей і сторінка),
requirements.txt, Vagrantfile, run-ec2.sh, check.py, expected.txt.

## Локальний запуск без VM

```bash
bash run-local.sh
```

Скрипт перевіряє версію Python, створює .venv, установлює requirements.txt і
запускає сервер на 127.0.0.1:8000. Змінні HOST і PORT перевизначають адресу.
Якщо в системі немає пакета python3-venv, скрипт зупиниться з поясненням.

Ті самі команди venv, pip і uvicorn працюють у Linux із Python 3.10+.
В іншому терміналі запустіть python3 check.py; результат має збігатися з expected.txt.
Ця перевірка підтверджує API, але не конфігурацію VirtualBox чи EC2.


## Віртуальна машина · Vagrant і VirtualBox

На хості з Vagrant і VirtualBox, у каталозі прикладу:

```bash
vagrant up
vagrant ssh
```

У гостьовій Ubuntu:

```bash
cd ~/lab1
HOST=0.0.0.0 bash run-local.sh
```

Відкрийте http://127.0.0.1:8080 на хості. Залиште термінал сервера відкритим.
Контроль: python3 check.py http://127.0.0.1:8080 на хості.
Для зупинки сервера натисніть Ctrl+C; вийдіть із SSH та виконайте vagrant halt.
Після повторного vagrant up застосунок запускається вручну тією самою командою.
vagrant destroy видаляє саме VM поточного проєкту; використовуйте після здачі.

## EC2 · Ubuntu Server

### Автоматичний запуск через user data

Вміст user-data.sh вставляється у поле **User data** під час створення інстанса
(Advanced details). cloud-init виконує його від root під час першого запуску:
установлює git і python3-venv, клонує відкритий репозиторій у /opt/passport,
готує .venv, створює службу systemd і запускає її.

Підключатися по SSH для старту не потрібно. Служба ввімкнена, тому застосунок
піднімається і після перезавантаження інстанса. Порт змінюється змінною PORT
на початку скрипту; узгодьте його з правилами Security Group.

Перевірка після запуску:

```bash
sudo systemctl status passport
```

Наприкінці /var/log/cloud-init-output.log мають бути п'ять рядків PASS —
скрипт сам виконує check.py всередині інстанса.

### Ручний запуск усередині наявного інстанса

Потрібен уже створений інстанс Ubuntu Server 22.04 або 24.04 LTS із доступом
до інтернету та SSH. Для AWS Academy оберіть образ і тип інстансу, дозволені
вашою навчальною сесією. Скрипт запускають **всередині VM**; він не створює
інстанс і не змінює мережеві правила AWS.

У SSH-сесії завантажте приклад:

```bash
sudo apt-get update
sudo apt-get install -y git
git clone https://github.com/lisnayk/znu-lecture-examples.git
cd znu-lecture-examples/conteinerization/01-virtualization/fastapi-vm
bash run-ec2.sh
```

Скрипт установлює системні пакети Python лише за потреби, створює .venv,
установлює requirements.txt і запускає сервер на 0.0.0.0:8000.
Повторний запуск використовує те саме оточення. Запуск можливий з іншого
каталогу: шляхи визначаються від місця розташування скрипту.
Не запускайте весь скрипт через sudo: він сам запросить права лише для apt.

В іншій SSH-сесії, у каталозі прикладу:

```bash
python3 check.py http://127.0.0.1:8000
```

Мають пройти всі п’ять перевірок із expected.txt. Для зовнішнього клієнта:

- інстанс повинен мати публічну IPv4-адресу й маршрут через Internet Gateway;
- у Security Group дозвольте TCP 22 для SSH і TCP 8000 для HTTP зі своєї
  поточної зовнішньої IP-адреси /32;
- перевірте також локальний firewall, якщо він увімкнений;
- відкрийте http://PUBLIC_IP:8000/ та http://PUBLIC_IP:8000/api/env.

Команда на комп’ютері клієнта з Python 3.10+ і копією прикладу:

```bash
python3 check.py http://PUBLIC_IP:8000
```

PUBLIC_IP замініть адресою інстансу. За потреби змініть порт:
`PORT=8080 bash run-ec2.sh`; узгодьте його з Security Group та адресами перевірки.

**Завершення:** Ctrl+C зупиняє сервер. Він працює у передньому плані SSH-сесії
і не запускається автоматично після перезавантаження. Після stop/start інстансу
перевірте його актуальну IP-адресу й повторіть `bash run-ec2.sh`.
Після завершення дослідження зупиніть або видаліть створені ресурси відповідно
до правил навчальної сесії; зупинка VM не видаляє EBS.

Перевірено запуск і всі п'ять перевірок check.py у локальному Linux
(Ubuntu 24.04 у WSL2, Python 3.12, 5 вересня 2026 року).
Запуск на EC2 та зовнішній мережевий доступ поки не перевірено:
навчальне середовище AWS Academy ще не надано.
