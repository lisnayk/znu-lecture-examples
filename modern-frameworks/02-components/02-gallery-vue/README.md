# FRAME — галерея на Vue 3

Приклад до лекції 2. Відтворює погоджений макет із сусіднього
каталогу `../01-gallery-native/gallery-bem/` — ту саму розмітку за БЕМ,
перекладену на однофайлові компоненти.

Задум прикладу: **межа БЕМ-блоку і є межа компонента**. Кожен блок
макета став окремим файлом `.vue`, а його стилі — блоком
`<style scoped lang="scss">` у тому ж файлі. Тому перехід від макета
до застосунку — переклад, а не переписування.

## Запуск у WSL

Потрібен Node.js 20.19+ або 22.12+ (відповідно до `engines`).
З каталогу цього прикладу:

```bash
npm install && npm run dev
```

Відкрити адресу, яку покаже Vite (зазвичай http://localhost:5173).
Зупинка: Ctrl+C. Складання для перевірки: `npm run build`.

## Розподіл обов'язків

| Компонент | Блок макета | Що вирішує | Вхід і вихід |
| --- | --- | --- | --- |
| `App` | `.page` | звідки беруться кадри й у якому порядку стоять частини сторінки | — |
| `Gallery` | `.gallery` | **який кадр показано** — єдиний стан застосунку | props `images` |
| `GalleryImage` | `.photo` | чи кадр завантажився | props `image` |
| `FrameInfo` | `.frame-info` | як виглядають підписи й номер | props `image`, `position`, `total` |
| `TagList` | `.tag-list` | показ переліку підписів | props `items` |
| `GalleryNavigation` | `.gallery-nav` | нічого; повідомляє про намір | props `disabled`, emits `previous`, `next` |
| `SiteHeader`, `SiteIntro`, `SiteFooter` | `.site-header`, `.intro`, `.site-footer` | постійні частини сторінки | — |
| `BaseBadge` | `.badge` | показ позначки | props `text` |

Стан живе в одному місці. `Gallery` зберігає `selectedId` — вибір
користувача, і тільки його; індекс, поточний кадр і кількість
обчислюються через `computed`. Дані рухаються вниз через props, наміри
користувача — вгору через події. `GalleryNavigation` не змінює вибір і
навіть не знає про нього, тому його можна перенести в інше місце
сторінки, нічого не переписуючи.

Власний стан має ще `GalleryImage` — стан завантаження фотографії.
Це його внутрішня справа: галереї про неї знати не потрібно.

Два екземпляри `Gallery` на одній сторінці працюють незалежно, бо стан
оголошено всередині компонента, а дані приходять ззовні.

## Стилі

```
src/styles/_tokens.scss   числа й кольори макета
src/styles/_mixins.scss   micro, медіазапити, обвідка фокуса
src/styles/main.scss      тема, скидання, типографіка сторінки
```

Токени й міксини Vite підставляє в кожен блок `<style lang="scss">`
через `css.preprocessorOptions.scss.additionalData`, тому імпортувати
їх у компонентах не потрібно. Сюди можна класти лише те, що саме по
собі не породжує CSS: змінні, міксини, функції.

Кольори оголошено двічі навмисно: SCSS-змінна в `_tokens.scss` і
властивість CSS у `main.scss`. SCSS-змінна зникає під час складання і
потрібна там, де значення має знати компілятор — насамперед у
медіазапиті. Властивість CSS живе в браузері, і лише її можна
перевизначити для окремого блоку або підмінити темою.

Решта стилів лежить у компонентах і має `scoped`: стиль не витікає за
межі блоку, тож імена класів усередині компонента не конфліктують із
рештою застосунку.

## Що виправлено проти першої версії макета

Композиція збережена; виправлено дефекти, які показала перевірка:

- контраст другорядного тексту 4.98:1 замість 4.18:1, межі кнопок
  3.42:1 замість 1.47:1, ціль кнопки 44 × 44;
- `width`, `height` і незмінна пропорція 3:2 прибирають стрибок
  розкладки; додано `preconnect` і `fetchpriority`;
- поки новий кадр вантажиться, попередній лишається видимим
  приглушено, а сусідні кадри завантажуються заздалегідь;
- гортання стрілками клавіатури, `tabular-nums` у лічильнику,
  `prefers-reduced-motion`.
