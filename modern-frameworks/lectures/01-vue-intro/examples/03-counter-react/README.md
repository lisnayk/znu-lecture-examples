# Лічильник на React

## Що це

Та сама задача засобами React. Показує іншу модель роботи зі станом: замість
змінюваного об'єкта — незмінні значення й функції-оновлювачі.

## Як воно працює

`useState` повертає поточне значення й функцію, якою його замінюють. Записати
в змінну напряму не можна: компонент перемальовується саме у відповідь на виклик
оновлювача.

Через це список не змінюють на місці, а створюють новий:
`setEntries([новий, ...entries])`. Це не примха бібліотеки, а умова, за якої
React бачить, що значення стало іншим.

Розмітка описана виразом JSX — це не рядок і не шаблон, а синтаксис, який
складальник перетворює на виклики функцій. Тому в ньому працюють звичайні
`map` і логічні оператори, а не окремі директиви.

## Як запустити

```bash
npm install && npm run dev
```

## Що має вийти

Поведінка та сама. Відмінності видно в коді: `className` замість `class`,
відсутність директив, обов'язковий `key` у списку.

## Що спробувати далі

Спробуйте змінити масив на місці — `entries.push(...)` замість створення нового.
Дані зміняться, а екран ні; це найкоротший спосіб побачити, на чому тримається
модель React.
